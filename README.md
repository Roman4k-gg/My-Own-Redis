# Redis Clone in Go

![CI](https://github.com/Roman4k-gg/My-Own-Redis/actions/workflows/ci.yml/badge.svg)
![Coverage](https://img.shields.io/badge/coverage-94.8%25-brightgreen)
![Go Version](https://img.shields.io/badge/go-1.23-blue)

In-memory база данных, совместимая с базовыми командами оригинального Redis. Написана с нуля на Go с использованием **исключительно стандартной библиотеки** — без сторонних фреймворков.

## Цель проекта

Глубокое понимание внутренних механизмов Redis: сетевое программирование, парсинг бинарных протоколов, многопоточность, управление памятью. Код специально написан без внешних зависимостей — только `net`, `sync`, `os/signal`, `strconv`.

## Архитектура

Кодовая база разделена на независимые пакеты:

```
cmd/server   — точка входа, TCP accept-loop, graceful shutdown
resp/        — парсер протокола RESP2 (сериализация/десериализация)
storage/     — потокобезопасная in-memory hash-таблица (TTL, GC, INCR)
handler/     — маршрутизатор команд (PING, ECHO, SET, GET, DEL, EXISTS, INCR)
aof/         — Append-Only File: журналирование команд и восстановление состояния
```

## Ключевые технические решения

### Concurrency: двухфазный GC без блокировки операций
Сборщик мусора для истёкших ключей работает в фоновой горутине. Критически важно: он **не блокирует GET/SET** на время сканирования:

```
Фаза 1 (RLock): сканируем все ключи → собираем список истёкших
Фаза 2 (WLock): удаляем только собранные ключи (минимальное время блокировки)
```

При shutdown горутина GC останавливается чисто через `done <-chan struct{}` — утечек горутин нет.

### Протокол RESP2
Собственный парсер бинарного протокола Redis RESP2 позволяет использовать стандартный `redis-cli` без изменений.

### Персистентность AOF
Все мутирующие команды (`SET`, `DEL`, `INCR`) журналируются на диск. При перезапуске AOF воспроизводится, полностью восстанавливая состояние базы.

### Graceful Shutdown
При получении `SIGINT`/`SIGTERM`:
1. Закрывается TCP listener — новые подключения не принимаются
2. `sync.WaitGroup` ожидает завершения всех активных обработчиков
3. Горутина GC останавливается через `done`-канал

## Поддерживаемые команды

| Команда | Описание |
|---------|----------|
| `PING [message]` | Проверка соединения |
| `ECHO message` | Возврат переданного сообщения |
| `SET key value [EX seconds]` | Установка значения с опциональным TTL |
| `GET key` | Получение значения |
| `DEL key [key ...]` | Удаление одного или нескольких ключей |
| `EXISTS key [key ...]` | Проверка существования ключей |
| `INCR key` | Атомарное увеличение целочисленного значения на 1 |

## Бенчмарки

Измерено на 13th Gen Intel Core i5-13500H, 16 параллельных горутин (`GOMAXPROCS=16`):

| Операция | ops/sec | ns/op | B/op | allocs/op |
|----------|---------|-------|------|-----------|
| `SET` (parallel) | **2 700 000** | 370 | 39 | 1 |
| `GET` (parallel) | **12 150 000** | 82 | 15 | 1 |
| `SET`+`GET` mix (parallel) | **4 860 000** | 205 | 13 | 1 |
| `INCR` (parallel) | **9 300 000** | 107 | 7 | 1 |

## Запуск

```bash
go run cmd/server/main.go
```

Подключение через стандартный `redis-cli`:

```bash
redis-cli -p 6379
127.0.0.1:6379> SET visits 0
OK
127.0.0.1:6379> INCR visits
(integer) 1
127.0.0.1:6379> INCR visits
(integer) 2
127.0.0.1:6379> SET key value EX 10
OK
127.0.0.1:6379> GET key
"value"
```

Тест персистентности (проверяет AOF восстановление):

```bash
python test.py
```
